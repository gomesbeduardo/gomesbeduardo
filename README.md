## 🧪 Como trabalho

<table>
  <tr>
    <td width="25%" valign="top"><b>📝 Spec antes do código</b><br /><sub>Escrevo uma spec curta, com critérios de aceite verificáveis, antes de cada mudança.</sub></td>
    <td width="25%" valign="top"><b>🔴 TDD</b><br /><sub>Escrevo o teste antes da implementação e vejo ele falhar.</sub></td>
    <td width="25%" valign="top"><b>🔍 PR com revisão e CI</b><br /><sub>Cada mudança entra por PR, e o CI roda testes, checagem de tipos e build.</sub></td>
    <td width="25%" valign="top"><b>📊 Avaliação reservada</b><br /><sub>Em recursos com IA, separo um conjunto de casos que fica fora do ajuste do prompt e rodo uma vez, no fim.</sub></td>
  </tr>
</table>

No [leadgate](https://github.com/gomesbeduardo/leadgate) você vê esse processo: specs versionadas, PRs revisados e mais de 400 testes automatizados.
