## How I work

<table>
  <tr>
    <td width="25%" valign="top"><b>📝 Spec before code</b><br /><sub>I write a short spec with verifiable acceptance criteria before each change.</sub></td>
    <td width="25%" valign="top"><b>🔴 TDD</b><br /><sub>I write the test before the implementation and watch it fail.</sub></td>
    <td width="25%" valign="top"><b>🔍 PR with review and CI</b><br /><sub>Each change goes through a PR, and CI runs tests, type checks and build.</sub></td>
    <td width="25%" valign="top"><b>📊 Held-out evaluation</b><br /><sub>For AI features, I keep a set of cases out of prompt tuning and run it once, at the end.</sub></td>
  </tr>
</table>

You can see this process in [leadgate](https://github.com/gomesbeduardo/leadgate): versioned specs, reviewed PRs and more than 400 automated tests.
